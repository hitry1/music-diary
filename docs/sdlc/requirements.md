# 뮤직 다이어리 — 요구사항 정의서 (requirements.md)

> STEP 1. 요구사항 분석 · 2026-11-10 · 작성: (본인) · AI: Claude Code (Claude Opus 5.5)

## 1. 서비스 개요

### 1.1 개발 목적
좋아하는 노래를 들어도 「언제, 어떤 기분으로, 왜 좋았는지」는 금방 잊힌다. 스트리밍 앱은 재생 기록만 남기고 감상은 남기지 않는다.
뮤직 다이어리는 곡을 검색해 **별점·기분·들은 날·한 줄 감상**을 남기고, 쌓인 기록을 다시 찾아보거나 통계로 내 취향을 돌아보게 하는 웹서비스이다.

### 1.2 사용자
- 음악을 자주 듣고 취향을 기록해 두고 싶은 대학생
- 데스크톱과 폰 브라우저에서 모두 사용한다.

### 1.3 기본 정보
| 항목 | 내용 |
|---|---|
| 개발 언어 / 프레임워크 | TypeScript(TSX) · React · Vite (`any` 타입 사용 안 함) |
| 화면 이동 | react-router-dom (Routes · Route) |
| 외부 Open API | iTunes Search API — 곡 검색(`/search`) · 곡 번호로 조회(`/lookup`, 쉼표로 여러 곡 한 번에), API 키 없음 |
| 데이터 저장 | 브라우저 LocalStorage (서버·데이터베이스 없음) |
| 공유 | 서버 없이 **공유 링크**로 — 고른 기록을 주소(`/shared/…`)에 담아 보내고, 받은 사람이 열어 보고 담는다 |
| 제공하지 않는 것 | 로그인·회원가입, 기기 간 동기화, 곡 재생(30초 미리듣기만), 서버에 올리는 공유·댓글 |

### 1.4 데이터
**곡(Track)** — iTunes API 응답에서 필요한 값만 골라 쓴다.

| 항목 | 타입 | 설명 |
|---|---|---|
| trackId | number | iTunes 곡 번호 |
| title | string | 곡 제목 |
| artist | string | 가수 |
| album | string | 앨범 이름 |
| artwork | string | 앨범 표지 주소(300×300) |
| previewUrl | string | 30초 미리듣기 주소(없을 수 있음) |
| genre | string | 장르 |
| releaseYear | string | 발매 연도 |

**감상 기록(Entry)** = 곡 정보 + 아래 항목. LocalStorage 에 배열로 저장한다.

| 항목 | 타입 | 설명 |
|---|---|---|
| id | number | 기록 번호(만든 시각, `Date.now()`) |
| rating | number | 별점 1~5 |
| mood | string | 기분 id (아래 6개 중 하나) |
| listenedAt | string | 들은 날 `YYYY-MM-DD` |
| memo | string | 한 줄 감상(0~300자) |
| createdAt / updatedAt | number | 만든 시각 / 고친 시각 |

**공유 항목(SharedItem)** — 공유 링크에 담는 값. 곡 정보는 담지 않고 곡 번호만 담아, 받는 쪽에서 lookup API 로 다시 가져온다(링크를 짧게).

| 항목 | 타입 | 설명 |
|---|---|---|
| t | number | trackId |
| r | number | 별점 1~5 |
| m | MoodId | 기분 |
| d | string | 들은 날 `YYYY-MM-DD` |
| n | string | 메모(공유할 때 앞 100자까지) |

링크 = `/shared/` + `encodeURIComponent(JSON.stringify(SharedItem 배열))` — 받는 쪽은 `useParams` 로 읽는다

**기분(Mood)** — 고정 6개: 신남😆 · 편안😌 · 슬픔😢 · 집중🎧 · 설렘💗 · 운동🔥

## 4. 업무 규칙

1. 기록은 **곡을 검색해서 고른 뒤에만** 만들 수 있다(곡 정보를 손으로 치지 않는다).
2. 별점(1~5)과 기분은 **필수**, 메모는 선택(최대 300자), 들은 날 기본값은 오늘.
3. 들은 날은 **오늘 이후로 정할 수 없다**(미래에 들은 곡은 없다). 날짜 칸(`max`)으로 막고, 저장할 때 한 번 더 검사한다.
4. 같은 곡을 여러 번 기록할 수 있다(다른 날 다시 들은 감상). 대신 이미 기록했다고 알려 준다.
5. 수정은 별점·기분·들은 날·메모만 — 곡 정보(제목·가수·표지)는 바꾸지 않는다.
6. 삭제는 확인 창에서 「확인」을 눌렀을 때만, 그 기록 하나만 지운다.
7. 기록은 LocalStorage 키 `music-diary-entries` 에 JSON 배열로 저장하고, 등록·수정·삭제 때마다 저장한다.
8. 통계는 따로 저장하지 않고 기록에서 그때그때 셈한다.
9. 미리듣기는 앱 전체에서 한 곡만 — 다른 곡을 누르면 앞 곡은 멈춘다.
10. 공유 링크에는 **지금 목록에 보이는 기록**(검색·거르기·정렬이 적용된 차례)을 앞에서부터 최대 20개 담는다. 메모는 앞 100자까지.
11. 공유받은 목록은 **읽기 전용**이다 — 그 화면에서는 수정·삭제하지 않는다. 고치려면 먼저 내 기록에 담는다.
12. 담을 때는 공유한 사람의 별점·기분·들은 날·메모를 그대로 쓰고, 새 기록 번호(id)를 붙인다.
13. 내 기록에 **같은 곡·같은 들은 날**의 기록이 이미 있으면 「이미 있음」으로 표시하고 담지 않는다.

## 5. 예외 처리

| ID | 상황 | 처리 |
|---|---|---|
| EX-01 | 검색어가 비어 있음(공백만) | API 를 부르지 않고 검색 전 안내를 보인다 |
| EX-02 | 검색 결과 0개 | 「「검색어」에 맞는 곡이 없어요」 |
| EX-03 | 네트워크 오류·HTTP 오류 | 오류 문구 + 「인터넷 연결을 확인하고 다시 시도해 주세요」 |
| EX-04 | 별점 없이 저장 | 「별점을 골라 주세요.」, 저장하지 않음 |
| EX-05 | 기분 없이 저장 | 「기분을 하나 골라 주세요.」, 저장하지 않음 |
| EX-06b | 들은 날이 비었거나 오늘 이후 | 「들은 날을 오늘이나 그 전으로 골라 주세요.」 |
| EX-06 | 메모 300자 초과 | 「메모는 300자까지 쓸 수 있습니다.」 |
| EX-07 | 없는 곡 번호로 `/track/:trackId` 에 들어옴 | 「곡을 찾을 수 없습니다」 + 곡 찾기 링크 (기록 쓰기 화면은 늘 주소의 곡 번호로 lookup API 를 부른다) |
| EX-08 | `/diary/:entryId` 의 기록이 없음 | 「기록을 찾을 수 없어요」 + 내 기록으로 가는 링크 |
| EX-09 | 미리듣기 주소가 없는 곡 | ▶ 버튼을 보이지 않는다 |
| EX-10 | 브라우저가 소리 재생을 막음 | 재생 상태로 바꾸지 않는다(버튼이 ▶ 그대로) |
| EX-11 | LocalStorage 값이 깨짐(JSON 아님) | 빈 목록으로 시작, 앱은 정상 |
| EX-12 | 기록이 하나도 없음 | 목록·통계에서 「아직 기록이 없어요」 + 곡 찾기 링크 |
| EX-13 | 거른 결과 0개 | 「조건에 맞는 기록이 없어요」 |
| EX-14 | 보이는 기록이 0개인데 공유 | 공유 버튼을 누를 수 없게 한다 |
| EX-15 | 보이는 기록이 20개 초과 | 앞 20개만 담고 「20개만 담았어요」라고 알린다 |
| EX-16 | 클립보드 복사가 막힘 | 링크를 글 상자에 보여 주어 손으로 복사할 수 있게 한다 |
| EX-17 | 링크의 데이터가 없거나 깨짐(JSON 아님) | 「열 수 없는 공유 링크예요」 + 곡 찾기 링크, 앱은 멈추지 않음 |
| EX-18 | 링크 값의 모양이 틀림(별점 6, 없는 기분, 날짜 형식 틀림 등) | 그 항목만 빼고 나머지를 보여 준다. 남은 것이 없으면 EX-17 |
| EX-19 | lookup 으로 찾을 수 없는 곡(판매 중지 등) | 그 항목만 「곡 정보를 찾을 수 없어요」로 표시하고 담기 버튼을 끈다 |
| EX-20 | 곡 정보 가져오기 실패(네트워크) | 오류 문구 + 「다시 시도」 버튼 |
